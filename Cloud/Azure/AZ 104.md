## Azure Architecture

![](Pasted%20image%2020260903104805.png)


![](Pasted%20image%2020260903104918.png)


- **Public Cloud** : Used by normal people
- **Sovereign Cloud** : Specially deployed and built for governments ( Currently **USA**, **Germany** and **China**)
- **Stack Hub** : Allows to run Azure services in a **disconnected state** (storms, ships etc) until connection comes back

> Fault domain : A server rack consisting of a **Top of the Rack** (TOR) switch and a **Power Distribution System** (PDU)

- Region Pair : A fault tolerance and failover feature that replicates data across a different region of **Microsoft's** choosing (Based on **power grid** setup)

### Tenant Root Group

The top-level parent node of your entire organization's resource hierarchy. Every tenant has exactly one Tenant Root Group. It acts as the ultimate governance container. Policies or RBAC roles assigned here apply to **every single management group, subscription, and resource** across the entire enterprise tenant.

### Management Groups

Organizational containers created under the root group to **group multiple Azure subscriptions** together. Can add upto 10,000 management groups across 6/7 layers deep. 

Grouping subscriptions by department, business unit, or environment type (e.g., creating a `Production` Management Group vs. a `Development` Management Group to apply different compliance policies to each).

### Subscription

The primary logical boundary for **billing**, **quotas**, and **administrative isolation**.

![513](Pasted%20image%2020260903113201.png)

Subscriptions tie resource usage directly to a single billing account and payment plan. Crucially, as shown by the dashed arrow pointing to Entra ID, every Azure Subscription trusts **exactly one Microsoft Entra tenant** to handle its authentication.

### Resource Groups

A logical folder or container deployed inside an Azure subscription to hold related assets.

![593](Pasted%20image%2020260903113421.png)

> Best practice to group resources based on similar lifecycle instead of resouce types

Grouping all the distinct infrastructure components of a single project together (e.g., placing the app server, database, and virtual network for a web dashboard in one `rg-analytics-prod` container).

- Tags : Provides metadata and context to objects. Can have upto 50 tags per object

![](Pasted%20image%2020260903224508.png)

### Types of Roles

- Reader : Has read access. Can only consume the resource
- Contributer : Has read & write access. Can change, modify, delete the resource but **cannot change the permissions**
- Owner : Can do everything (**read, write, permission control**)

Inside Azure Virtual Networking, Azure takes the first three available addresses of the network space (aside from host bit and network bit).

- Second & Third address : DNS servers
